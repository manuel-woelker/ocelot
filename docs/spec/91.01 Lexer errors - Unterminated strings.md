# What lexer errors are specified first?

The first lexer error the spec commits to is an unterminated string literal.
This is a good starting point because the failure is common, easy to recognize, and should stop parsing immediately.

# What rules should readers assume first?

For the first version of lexer diagnostics:

- string literals start with `"` and must end with a matching `"`
- reaching the end of the line or file without a closing `"` is an error
- lexer errors are reported before later compilation stages can continue
- the stable spec-facing error text is the diagnostic headline

This keeps the diagnostic contract small while the richer rendered source excerpts are still evolving.

# What happens when a string literal is not closed?

An unterminated string literal must fail compilation with a lexer error.

## Example: unterminated strings are rejected

```ocelot
println("hello);
```

### Error

```text
unterminated string literal
```
