# How do test items affect normal script execution?

Test items do not run when a file is executed as a normal script.
Only executable top-level statements participate in ordinary script execution.

This ensures that adding tests to a source file does not silently change the behavior of `ocelot <script-file>`.

# What rules should readers assume first?

For the first version of the runtime model:

- top-level statements execute in source order
- test items are discovered by test tooling, not by normal script execution
- a file may contain only test items, only executable statements, or a mixture of both

More detailed rules for project-wide test discovery and assertion behavior can come later.

# What happens when a file contains only test items?

Executing a file that contains only test items produces no ordinary script output.

## Example: test-only files are inert during script execution

main.ocelot:

```ocelot
test "prints one line" {
    println("hello");
}
```

### Output

```text
```

# What happens when statements and test items are mixed?

Normal execution still evaluates only the executable statements.
Test items remain present in the file but are skipped by script execution.

## Example: mixed files skip test bodies during script execution

main.ocelot:

```ocelot
println("before");

test "would print during testing" {
    println("inside test");
}

println("after");
```

### Output

```text
before
after
```
