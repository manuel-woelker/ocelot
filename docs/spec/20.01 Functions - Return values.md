# How do functions declare a result?

Place `-> string`, `-> bool`, or `-> ()` after the parameter list and before
any `can` and `cannot` clauses. An omitted result annotation means unit (`()`).
Return types are resolved before bodies, so forward, recursive, imported, and
qualified calls use their declared type. Existing keyword and positional argument
rules apply unchanged. Unknown result types and `any` results are rejected.

`return expression;` returns an evaluated value. Its type must match the result
declaration. A bare `return;` returns unit and is valid only in a unit function.
Returns are allowed in function bodies, including `main`, but not in script or
test bodies. Native declarations must match their registered result type; the
current core functions return unit.
`return` is a reserved keyword.

## Example: string and boolean results compose as call arguments

main.ocelot-script:

```ocelot
fun greeting(name: string) -> string {
    return "Hello ${name}!";
}

fun invert(value: bool) -> bool {
    return not value;
}

println(greeting(name: "Ada"));
assert(invert(value: false));
assert_eq(expected: "Hello Grace!", actual: greeting(name: "Grace"));
```

### Output

```text
Hello Ada!
```

# When does a return stop execution?

A return exits only its current function. Statements after it do not execute,
and the caller continues after receiving the result. All statements still undergo
static checking, even after a return; effect inference remains conservative across
the entire body. Direct module execution discards the result of `main()` rather
than mapping it to a process exit code.

## Example: early unit returns skip subsequent effects

main.ocelot-script:

```ocelot
fun done() -> () {
    println("before");
    return;
    println("unreachable");
}

done();
println("caller continues");
```

### Output

```text
before
caller continues
```

# What happens if a function finishes without an explicit return?

The body produces its [block result](./02.04%20Expressions%20-%20Blocks.md), which
must match the declared result type. A final expression without a semicolon
supplies that value; a discarded final expression or empty body produces unit.
Every explicit return is also checked, including returns in unreachable code.

## Example: a semicolon discards a function body's final expression

execute:

```ocelot
fun ignored() {
    "discarded";
}
```

eval:

```ocelot
ignored()
```

### Eval result

```text
()
```

# How are typed values returned through embedded eval?

Embedded eval returns a function's result directly and uses the existing value
rendering. It does not require printing the result.

## Example: embedded eval receives an explicitly returned string

execute:

```ocelot
fun greeting(name: string) -> string {
    return "Hello ${name}!";
}
```

eval:

```ocelot
greeting(name: "Ada")
```

### Eval result

```text
"Hello Ada!"
```

# How are invalid returns reported?

Return placement, missing returns, and result-type mismatches are compilation
errors with source diagnostics. The program does not execute when these checks fail.

## Example: a non-unit function cannot fall through

main.ocelot-script:

```ocelot
fun missing() -> string {}
```

### Error

```text

  ╭▸ main.ocelot-script:1:5
```

## Example: return values must match the declared type

main.ocelot-script:

