# How are values compared?

Use `==` to test equality and `!=` to test inequality. Both produce `bool` and
require matching operand types: `string`, `bool`, or `()`. Strings compare their
exact contents without Unicode normalization; booleans compare their values;
unit equals unit. There are no implicit conversions. These checks also apply
when the result is discarded or the expression is in an unselected branch.
Single `=` remains reserved for binding initialization.

## Example: equality compares values of matching types

main.ocelot-script:

```ocelot
let name = "Ada";
println(name == "Ada");
println(name != "Grace");
println(true == false);
println(false != false);
println({} == {});
println({} != {});
println("é" == "é");
```

### Output

```text
true
true
false
false
true
false
true
```

# What is equality's precedence?

Calls bind more tightly than `not`, and `not` binds more tightly than equality.
Thus `not enabled() == false` compares the negated call result with `false`.
Chained comparisons such as `a == b == c` or `a != b == c` are rejected.
Use [block results](<02.04 Expressions - Blocks.md>) to group an equality result
or negate an entire comparison, for example `not { a == b }`.

## Example: comparisons compose with calls, negation, blocks, and conditionals

main.ocelot-script:

```ocelot
fun enabled() -> bool {
    true
}

let matches: bool = not enabled() == false;
if matches == true {
    println("matched");
};
println(not {
    "Ada" == "Grace"
});
println({
    true != false
} == true);
println("equal: ${enabled() == true}");
```

### Output

```text
matched
true
true
equal: true
```

# In what order are operands evaluated?

Evaluate the left operand once, then the right operand once, then compare their
values. Both are evaluated even when the left value is `false`. A return or runtime
error stops evaluation immediately. A non-fallthrough operand makes the entire
comparison non-fallthrough; all operand names, nested expressions, and effects
still undergo static checking.

## Example: both operands run once from left to right

main.ocelot-script:

```ocelot
println({
    println("left");
    false
} == {
    println("right");
    true
});
```

### Output

```text
left
right
false
```

## Example: returning from the left skips the right operand

main.ocelot-script:

```ocelot
fun early() -> string {
    {
        return "early";
    } != {
        println("unreachable");
        true
    };
    "also unreachable"
}

println(early());
```

### Output

```text
early
```

# How are invalid comparisons reported?

Type mismatches and ambiguous chains fail before running the program.

## Example: mixed operand types are rejected

main.ocelot-script:

```ocelot
true == "true";
```

### Error

```text
error: operator `==` expects matching operand types: got bool and string
  ╭▸ main.ocelot-script:1:1
  │
1 │ true == "true";

```

## Example: equality comparisons cannot be chained

main.ocelot-script:

```ocelot
true == false != true;
```

