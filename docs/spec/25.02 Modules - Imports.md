# What does a `use` item import?

A `use` item imports one or more exported functions from another module into the current file.
That allows the imported function names to be used without repeating the full module path at every call site.

# What forms of `use` are supported?

The first import slice supports two forms:

- `use helper::greet;`
- `use math::trig::{sin, cos};`

This means:

- `use helper::greet;` imports exactly one function name
- `use math::trig::{sin, cos};` imports several function names from the same module
- imports are file-local and do not re-export names to other modules
- fully qualified calls such as `helper::greet()` remain valid even when the same function is imported

The current scope limits are intentional:

- no aliasing such as `use helper::greet as hello`
- no wildcard imports such as `use helper::*`
- no nested grouped paths such as `use math::{trig::sin, trig::cos}`

# How does a script use one imported function?

## Example: a script can call one imported function

main.ocelot-script:

```ocelot
use helper::greet;

greet();
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# How does a grouped import work?

## Example: a script can import several functions from one module

main.ocelot-script:

```ocelot
use helper::{greet, wave};

greet();
wave();
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}

fun wave() {
    println("bye");
}
```

### Output

```text
hello
bye
```

# Can imported names be used inside functions in the importing file?

Yes.
Imports belong to the file, not only to its top-level statements.

## Example: imported functions are visible inside local functions

main.ocelot:

```ocelot
use helper::greet;

fun main() {
    run();
}

fun run() {
    greet();
}
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when an imported module does not exist?

The resolver reports the same unknown-module error used by fully qualified calls.

## Example: importing from an unknown module is a resolver error

main.ocelot-script:

```ocelot
use helper::greet;
```

### Error

```text
error: unknown module `helper`
  ╭▸ main.ocelot-script:1:5
  │
1 │ use helper::greet;
  ╰╴    ━━━━━━ unknown module
at main.ocelot-script:1:5
```

# What happens when the module exists but the imported function does not?

## Example: importing a missing function is a resolver error

main.ocelot-script:

```ocelot
use helper::greet;
```

helper.ocelot:

```ocelot
fun wave() {}
```

### Error

```text
error: module `helper` has no function `greet`
  ╭▸ main.ocelot-script:1:13
  │
1 │ use helper::greet;
  ╰╴            ━━━━━ unknown function
at main.ocelot-script:1:13
```

# What happens when the same local name is imported more than once?

Duplicate imports are rejected instead of using import order as a shadowing rule.

## Example: duplicate imports are a resolver error

main.ocelot-script:

```ocelot
use helper::greet;
use helper::greet;
```

helper.ocelot:

```ocelot
fun greet() {}
```

### Error

```text
error: duplicate import `greet`
  ╭▸ main.ocelot-script:2:13
  │
2 │ use helper::greet;
  ╰╴            ━━━━━ duplicate import
at main.ocelot-script:2:13
```
