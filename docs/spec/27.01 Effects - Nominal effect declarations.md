# What is a nominal effect declaration?

A nominal effect declaration introduces an effect name that functions may mention in `can` and `cannot` clauses.
Effects are lightweight labels, not executable statements.

- effects are declared as `effect <name>;`
- names in function effect clauses must resolve to declared effects
- `can <effect>` explicitly declares or introduces that effect on the function
- `cannot <effect>` forbids that effect from the function body and everything it reaches
- effects propagate upward through function calls
- builtin effects are declared by the compiler-provided `core` module and are available without explicit user declarations:
  - `write_stdout` for `println()`
  - `panic` for `assert()` and `assert_eq()`

There are no effect variables, effect polymorphism, or effect lists yet.

# Can a function combine effect clauses?

A function may declare one `can` clause followed by one `cannot` clause.

## Example: a function may declare both `can` and `cannot`

main.ocelot-script:

```ocelot
effect exec;

fun worker() can exec cannot panic {}
```

### Output

```text
```

# How do effects propagate through calls?

If one function has an effect, callers inherit that effect transitively.
That is true both for explicitly declared `can` effects and for core-declared effects introduced by called functions.

## Example: a caller inherits a callee's declared effect

main.ocelot-script:

```ocelot
effect exec;
fun child() can exec {}
fun parent() {
    child();
}
parent();
```

### Output

```text
```

## Example: core effects do not need explicit user declarations

main.ocelot-script:

```ocelot
fun log() {
    println("hello");
}
fun check() {
    assert(true);
}
log();
check();
```

### Output

```text
hello
```

# What happens when a function forbids an effect?

A function with `cannot <effect>` must not directly or transitively have that effect.

## Example: `cannot` rejects transitive effect propagation

main.ocelot-script:

```ocelot
effect exec;
fun child() can exec {}
fun parent() cannot exec {
    child();
}
```

## Example: `cannot` rejects effects through multiple call layers

main.ocelot-script:

```ocelot
effect exec;

fun leaf() can exec {}
fun middle() {
    leaf();
}
fun root() cannot exec {
    middle();
}
```
