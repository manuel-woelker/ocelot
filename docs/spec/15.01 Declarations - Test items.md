# What is a test item?

A test item is a top-level declaration that defines code intended for test execution.
It is introduced with the `test` keyword, followed by a string name and a block body.

Unlike an ordinary script statement, a test item is not executed during normal script execution.

# What rules should readers assume first?

For the first version of the spec:

- a test item is declared as `test "name" { ... }`
- the name is required and is written as a string literal
- the body contains zero or more ordinary statements
- test items may appear alongside executable top-level statements

This keeps the first test model explicit without introducing function declarations, attributes, or assertion syntax yet.

# What does the smallest test item look like?

The smallest useful test item has a name and one statement in its body.

## Example: a file can declare one test item

main.ocelot-script:

```ocelot
test "prints one line" {
    println("hello");
}
```

### Output

```text
```

# How can test items coexist with ordinary script code?

Top-level executable statements and test items may appear in the same file.
The statements remain part of normal script execution, while the test item remains available for a test runner.

## Example: a file can mix script statements and test items

main.ocelot-script:

```ocelot
println("setup");

test "prints one line" {
    println("hello");
}
```

### Output

```text
setup
```
