# What lexer error applies to unterminated block comments?

An unterminated block comment is a lexer error.
This matters because block comments can nest, so the lexer must keep scanning until every opened `/*` has a matching `*/`.

# What rules should readers assume first?

For the first version of block-comment diagnostics:

- block comments start with `/*` and end with `*/`
- nested block comments must also be closed before lexing can continue
- reaching the end of the file before the final closing delimiter is an error
- lexer errors are reported before later compilation stages can continue
- spec examples compare the full rendered diagnostic output

# What happens when a block comment is not closed?

An unterminated block comment must fail compilation with a lexer error.

## Example: unterminated block comments are rejected

main.ocelot:

```ocelot
println(/* hello
```

### Error

```text
error: unterminated block comment
  ╭▸ main.ocelot:1:9
  │
1 │ println(/* hello
  ╰╴        ━━━━━━━━ block comment is missing a closing `*/`
at main.ocelot:1:9
```
