# Which integer operators are supported?

Unary `-` negates an integer. Binary `+`, `-`, `*`, and `/` produce `int`.
Division truncates toward zero. Ordering `<`, `<=`, `>`, and `>=` produces `bool`.
All operands must be integers. [Equality](<02.06 Expressions - Equality.md>)
also accepts matching integers. There are no implicit conversions.

# How are operations grouped and evaluated?

There is no operator precedence. Different operators require explicit
[parentheses](<02.07 Expressions - Parentheses.md>), including unary minus:
write `(-3) * 4`, `x - (-y)`, and `(1 + 2) * 3`. Even `-3 - 4` requires grouping;
prefix forms are always grouped when combined with binary forms. Repeated unary
minus is valid. Homogeneous arithmetic chains evaluate left to right; ordering
and equality cannot chain. Calls, blocks, and interpolation delimit expressions.
Operands run exactly once, left to right; returns and errors stop evaluation.

## Example: all integer operators have exact results

main.ocelot-script:

```ocelot
println(1 + 2 + 3);
println(20 - 5 - 3);
println(2 * 3 * 4);
println(24 / 3 / 2);
println((-7) / 3);

println(- -3);
println(-(1 + 2));
println((1 + 2) * 3);
println(1 < 2);
println(2 <= 2);
println(3 > 2);
```


## Example: operands run once in source order and returns propagate

main.ocelot-script:

```ocelot
fun record(name: string, value: int) -> int {
    println(name);
    value
}

fun left_return() -> int {
    ({
        return 11;
    }) + record(name: "skipped", value: 0)
}

fun right_return() -> int {
    record(name: "before-return", value: 3) * {
        return 12;
    }
}

fun negative_return() -> int {
    -{
        return 13;
    }
}

println(record(name: "left", value: 7) - record(name: "right", value: 2));
println(left_return());
println(right_return());
println(negative_return());
```

### Output

```text

right
5
11
before-return
12
13
```

# What happens when an integer operation fails?

All builds check overflow, including intermediate results and negation of minimum
int. Division by zero and minimum int divided by -1 fail too. Failures are
source-located language runtime errors, identical in interpretation and native C.
Skipped branches and short-circuited operands do not execute failing operations.

## Example: safe boundary operations and skipped failures succeed

main.ocelot-script:

```ocelot

let max = 9223372036854775807;
```

# Which effects and static checks apply?

Arithmetic and unary negation conservatively contribute `panic`, even for
constants or skipped code. Ordering and equality add no effect of their own.
Both operands still undergo name, type, return, and effect checking.

## Example: ordering and equality do not introduce panic

main.ocelot-script:

```ocelot
fun ordered(left: int, right: int) -> bool cannot panic {
    (left <= right) and (left != right)
}

assert(ordered(left: 1, right: 2));
```
