# What is a function call expression?

A function call expression invokes a callable name using parentheses.
The arguments appear in source order inside the parentheses.

- the callee is an identifier or `::`-qualified identifier path
- arguments are separated by commas
- each argument is written as `parameter: expression`, unless its parameter permits omission
- parameters declared with `positional` accept either a labeled or an unlabeled argument
- arguments follow declaration order; labels do not permit reordering
- unlabeled arguments precede labeled arguments, and all values evaluate left to right
- a call expression can be used as an expression statement
- the caller must supply exactly the number of arguments declared by the callee
- each argument must match the callee's declared parameter type
- all currently supported functions return unit (`()`); a nested call cannot supply a `bool` or `string` argument

See [function definitions](./15.02%20Declarations%20-%20Function%20definitions.md) for declarations and parameter bindings,
and [core lookup](./25.03%20Modules%20-%20Core%20module.md) for unqualified name precedence.

## Example: a call expression can pass typed arguments to a user-defined function

main.ocelot-script:

```ocelot
fun greet(name: string) {
    println(name);
}

greet(name: "hello");
```

### Output

```text
hello
```

# When may a label be omitted?

Only parameters declared with `positional` permit omission. The same parameter
still accepts its explicit label. `println` permits omission of `value`, and
`assert` permits omission of `condition`. `assert_eq` requires `expected:` and
`actual:`. This policy belongs to the declaration and applies to qualified and
imported calls as well as local calls.

## Example: positional parameters permit either call style

main.ocelot-script:

```ocelot
fun greet(positional name: string, excited: bool) {
    println("${name} ${excited}");
}

greet("Ada", excited: true);
greet(name: "Grace", excited: false);
println(value: "explicit");
assert(condition: true);
assert_eq(expected: "same", actual: "same");
```

### Output

```text
Ada true
Grace false
explicit
```

# What happens when a required label is omitted?

The resolver rejects omitted required labels, unknown or duplicate labels, and
arguments supplied out of declaration order before executing the program.
Parameter names are part of a function's public calling interface; renaming one
requires updating labeled callers.

## Example: ordinary parameters require labels

main.ocelot-script:

```ocelot
fun greet(name: string) {}
greet("Ada");
```

### Error

```text
error: argument `name` to `greet` requires a label
  ╭▸ main.ocelot-script:2:7
  │
2 │ greet("Ada");
  ╰╴      ━━━━━ write `name: ...`
at main.ocelot-script:2:7
```

# What happens when a call names no known function?

The resolver rejects calls whose callee name does not exist in the program environment.

## Example: calling an unknown function is a resolver error

main.ocelot-script:

```ocelot
printline("hello");
```

### Error

```text
error: unknown function `printline`
  ╭▸ main.ocelot-script:1:1
  │
1 │ printline("hello");
  ╰╴━━━━━━━━━ unknown function
at main.ocelot-script:1:1
```

# What happens when a call uses the wrong argument type?

The resolver rejects call arguments whose types do not match the callee signature.

## Example: user-defined calls reject wrong argument types

main.ocelot-script:

```ocelot
fun greet(excited: bool) {}

greet(excited: "hello");
```

### Error

```text
error: type error: argument 1 to `greet` must be bool
  ╭▸ main.ocelot-script:3:16
  │
3 │ greet(excited: "hello");
  ╰╴               ━━━━━━━ expected bool
at main.ocelot-script:3:16
```
