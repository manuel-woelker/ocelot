# What is the `core` module?

`core` is a compiler-provided module that declares native functions and builtin effects.
It is part of the language surface, even though its implementations are supplied by the compiler and runtime.

`core` is loaded automatically, and its module name is reserved. Unqualified
function calls search in this order:

1. Functions declared in the current module.
2. Explicit file-local imports.
3. Functions in `core`.

Qualified calls such as `core::println()` bypass this fallback order.

# How does fallback lookup interact with local declarations?

Local functions take precedence over the `core` fallback.

## Example: a local function outranks the fallback `core` import

main.ocelot-script:

```ocelot
fun println() {
    core::println("local");
}

println();
```

### Output

```text
local
```

# How does fallback lookup interact with explicit imports?

Explicit imports take precedence over the `core` fallback.

## Example: an explicit import outranks the fallback `core` import

main.ocelot-script:

```ocelot
use helper::println;

println();
```

helper.ocelot:

```ocelot
fun println() {
    core::println("helper");
}
```

### Output

```text
helper
```
