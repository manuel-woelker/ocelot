# What is the `core` module?

`core` is a compiler-provided module that declares native functions and builtin effects.
It is part of the language surface, even though its implementations are supplied by the compiler and runtime.

# What rules should readers assume first?

For the first version of the spec:

- `core` is loaded automatically for every program
- unqualified calls may fall back to functions declared in `core`
- explicit imports and local declarations outrank that fallback
- qualified names such as `core::println()` remain valid
- the module name `core` is reserved for the compiler-provided module

This keeps builtin functionality visible as a real module without forcing every file to write boilerplate imports for `println`, `assert`, and `assert_eq`.

# How does fallback lookup interact with local declarations?

Local functions should win before fallback lookup reaches `core`.

## Example: a local function outranks the fallback `core` import

main.ocelot-script:

```ocelot
fun println() {
    core::println("local");
}

println();
```

### Output

```text
local
```

# How does fallback lookup interact with explicit imports?

Explicit imports should also win before fallback lookup reaches `core`.

## Example: an explicit import outranks the fallback `core` import

main.ocelot-script:

```ocelot
use helper::println;

println();
```

helper.ocelot:

```ocelot
fun println() {
    core::println("helper");
}
```

### Output

```text
helper
```
