# What does a successful eval return?

A successful embedded `eval` returns one runtime value.
The spec compares that returned value directly instead of requiring examples to print it.

# How should eval results be rendered in spec examples?

For spec purposes, eval results use a stable textual rendering:

- booleans render as `true` or `false`
- strings render as quoted string literals
- unit renders as `()`

This keeps returned values distinct from ordinary printed output.

# How does a boolean eval result render?

Boolean values render using their source literal spelling.

## Example: boolean eval returns `true`

eval:

```ocelot
not false
```

### Eval result

```text
true
```

# How does a string eval result render?

String values render with quotes so they are visibly different from printed output text.

## Example: string eval results stay quoted

eval:

```ocelot
"hello"
```

### Eval result

```text
"hello"
```

# How does a unit eval result render?

Calls that do not produce a more specific value return unit.

## Example: calling `println` returns unit

eval:

```ocelot
println("hello")
```

### Eval result

```text
()
```

# How are eval failures rendered?

Eval failures use the same stable error rendering approach as other spec-validation failures.

## Example: unresolved identifiers still surface as errors during eval

eval:

```ocelot
missing_value
```

### Error

```text
unresolved identifier `missing_value`
```
