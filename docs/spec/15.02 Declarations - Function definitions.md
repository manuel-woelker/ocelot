# What is a function definition?

A function definition is a top-level declaration that gives a callable name a block body.
It is introduced with the `fun` keyword, followed by an identifier name, an empty parameter list, and a block body.

# What rules should readers assume first?

For the first version of the spec:

- a function is declared as `fun name() { ... }`
- the function name is required and is written as an identifier
- the parameter list must be present and must currently be empty
- the body contains zero or more ordinary statements
- function definitions may appear alongside executable top-level statements and test items
- calls may resolve functions declared later in the same file

This keeps the first function model small while still making declarations useful.

# What does the smallest function definition look like?

The smallest function definition has a name and an empty body.

## Example: a file can declare one function

```ocelot
fun greet() {}
```

### Output

```text
```

# Can a call resolve a later function definition?

Yes.
Function declarations are added to the function table before call expressions are resolved, so forward references work in the first slice.

## Example: a call can target a function declared later in the file

```ocelot
greet();

fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when two functions share the same name?

Function names must be unique across user-defined and native functions.

## Example: duplicate function names are a resolver error

```ocelot
fun greet() {}
fun greet() {}
```

### Error

```text
error: duplicate function `greet`
  ╭▸ spec-test.ocelot:2:5
  │
2 │ fun greet() {}
  │     ━━━━━ duplicate function
  │
  ⸬  spec-test.ocelot:1:5
  │
1 │ fun greet() {}
  ╰╴    ━━━━━ already defined here
at spec-test.ocelot:2:5
```
