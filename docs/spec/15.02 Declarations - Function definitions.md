# What is a function definition?

A function definition is a top-level declaration that gives a callable name a block body.
It is introduced with the `fun` keyword, followed by an identifier name, a parameter list, and a block body.

# What rules should readers assume first?

For the first version of the spec:

- a function is declared as `fun name(param: type, ...) { ... }`
- a function may optionally include `can <effect>` and `cannot <effect>` clauses after `()`
- if both effect clauses are present, `can` appears before `cannot`
- the function name is required and is written as an identifier
- the parameter list must be present
- each parameter is written as `name: type`
- parameter types are currently limited to `string` and `bool`
- the body contains zero or more ordinary statements
- function definitions may appear alongside executable top-level statements and test items
- calls may resolve functions declared later in the same file
- a function named `main` has no special syntax; its special role, when present, comes from module execution rules

This keeps the first function model small while still making declarations useful.

# What does a parameterized function definition look like?

Parameters are part of the declaration header and become immutable local bindings inside the function body.

## Example: a function can declare typed parameters

main.ocelot-script:

```ocelot
fun greet(name: string, excited: bool) {
    println(name);
    assert(excited);
}

greet("hello", true);
```

### Output

```text
hello
```

# What does the smallest function definition look like?

The smallest function definition has a name and an empty body.

## Example: a file can declare one function

main.ocelot-script:

```ocelot
fun greet() {}
```

### Output

```text
```

# How do effect clauses fit into function definitions?

Functions may optionally advertise one allowed effect, one forbidden effect, or both.

## Example: a function may declare both `can` and `cannot`

main.ocelot-script:

```ocelot
effect exec;

fun worker() can exec cannot panic {}
```

### Output

```text
```

# Can a call resolve a later function definition?

Yes.
Function declarations are added to the function table before call expressions are resolved, so forward references work in the first slice.

## Example: a call can target a function declared later in the file

main.ocelot-script:

```ocelot
greet();

fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when two functions share the same name?

Function names must be unique within the same module.

## Example: duplicate function names are a resolver error

main.ocelot-script:

```ocelot
fun greet() {}
fun greet() {}
```

### Error

```text
error: duplicate function `greet`
  ╭▸ main.ocelot-script:2:5
  │
2 │ fun greet() {}
  │     ━━━━━ duplicate function
  │
  ⸬  main.ocelot-script:1:5
  │
1 │ fun greet() {}
  ╰╴    ━━━━━ already defined here
at main.ocelot-script:2:5
```

# What happens when two parameters share the same name?

Parameter names must be unique within one function declaration.

## Example: duplicate parameter names are a resolver error

main.ocelot-script:

```ocelot
fun greet(name: string, name: bool) {}
```

### Error

```text
error: duplicate parameter `name`
  ╭▸ main.ocelot-script:1:25
  │
1 │ fun greet(name: string, name: bool) {}
  │                         ━━━━ duplicate parameter
  │
  ⸬  main.ocelot-script:1:11
  │
1 │ fun greet(name: string, name: bool) {}
  ╰╴          ━━━━ already defined here
at main.ocelot-script:1:25
```
