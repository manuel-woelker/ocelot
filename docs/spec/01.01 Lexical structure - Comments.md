# What comment forms does `ocelot` support?

`ocelot` supports line comments and block comments.
Comments are part of lexical structure, not executable syntax, so they are ignored the same way whitespace is ignored.

# What rules should readers assume first?

For the first version of comment syntax:

- `//` starts a line comment that continues to the end of the line
- `/* ... */` starts a block comment that may span multiple lines
- block comments nest
- comments may appear anywhere whitespace may appear
- comment markers inside string literals are ordinary text, not comments

This keeps comments useful without introducing doc comments or source-preserving semantics yet.

# How does a line comment behave?

A line comment starts with `//` and runs until the next newline or the end of the file.

## Example: a line comment is ignored before a statement

main.ocelot:

```ocelot
// greet the user
println("hello");
```

### Output

```text
hello
```

# How does a nested block comment behave?

A block comment starts with `/*` and ends with the matching `*/`.
If another `/*` appears before the closing delimiter, the nested comment must close before the outer comment closes.

## Example: nested block comments are ignored

main.ocelot:

```ocelot
/* outer comment
   /* nested detail */
*/
println("hello");
```

### Output

```text
hello
```

# How do comments interact with executable code?

Comments may appear between tokens without changing the meaning of the surrounding code.

## Example: comments can appear inside a call expression

main.ocelot:

```ocelot
println(/* value */ "hello");
```

### Output

```text
hello
```
