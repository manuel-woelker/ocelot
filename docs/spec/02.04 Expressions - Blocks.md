# What value does a block produce?

A block is an expression written as `{ ... }`. Its final expression supplies its
value when written without a semicolon. A semicolon discards that expression's
value; a block with no final result expression produces unit (`()`). Empty blocks
also produce unit. Statements execute in source order.

Blocks may appear wherever expressions are accepted, including call arguments,
negation, and template interpolation. A block used as a discarded statement needs
a semicolon, even when followed by another statement. A semicolon-free result
must be the last expression before the closing brace.
[Conditionals](./02.05%20Expressions%20-%20Conditionals.md) are expressions too:
their selected branch supplies a block result, and `;` discards the conditional's value.

## Example: nested blocks supply string and boolean values

main.ocelot-script:

```ocelot
println({
    println("before");
    {
        "value"
    }
});
assert(not {
    false
});
assert_eq(expected: {}, actual: {
    true;
});
```

### Output

```text
before
value
```

# How do function bodies use block results?

Function bodies use the same rule. Their result must match the declared return
type; omission of a result annotation still means unit, without inferring a type
from the body. A function may either finish with a matching result or explicitly
return as described in [return values](./20.01%20Functions%20-%20Return%20values.md).
Test bodies must produce unit and cannot return from a function.

## Example: a function body returns its tail expression

execute:

```ocelot
fun greeting(name: string) -> string {
    "Hello ${name}!"
}
```

eval:

```ocelot
greeting(name: "Ada")
```

### Eval result

```text
"Hello Ada!"
```

# Does returning from a nested block exit only that block?

An explicit return exits the enclosing function, including when the block is
inside another expression. Later arguments and effects are skipped. A called
function consumes its own returns and supplies its result to the caller.
Blocks that always return do not produce a normal value and are accepted in
any expected result position. All contained expressions still undergo static
checking, and effects are conservatively tracked even in unreachable code.

## Example: an argument block returns before the call or later arguments execute

main.ocelot-script:

```ocelot
fun early() -> string {
    assert_eq(expected: {
        return "early";
    }, actual: println("unreachable"));
    "also unreachable"
}

println(early());
```

### Output

```text
early
```

# How do blocks nest inside template interpolation?

An interpolation's closing brace is distinct from any braces in its expression.
Nested blocks and nested templates retain their own boundaries.

## Example: template interpolation evaluates nested block results

main.ocelot-script:

```ocelot
println("value ${{
    {
        true
    }
}}");
```

### Output

```text
value true
```
