# What is a file module?

Every `.ocelot` file defines a module automatically.
The module name is the file path relative to the execution root, with the `.ocelot` extension removed and path segments separated by `::`.

# What rules should readers assume first?

For the first version of the module system:

- `main.ocelot` defines module `main`
- `helper.ocelot` defines module `helper`
- `math/greet.ocelot` defines module `math::greet`
- `.ocelot-script` files are executable scripts, not modules
- every function defined in a file is exported from that module
- module functions are called with fully qualified names such as `helper::greet()` or `math::greet::hello()`
- the engine eagerly loads all `.ocelot` files under the entry file's directory
- `.ocelot` module files may not contain top-level statements
- running a `.ocelot` file directly resolves and executes its module-local `main()` function
- that `main()` entrypoint is an ordinary `fun main() { ... }` declaration with the same empty parameter list rules as other functions
- if a directly executed `.ocelot` file does not define `main()`, execution fails before interpretation begins

This keeps modules simple and filesystem-shaped, with imports layered on separately.

# How does a script call a sibling module function?

The entry file can call a function exported from a sibling file by naming the sibling module explicitly.

## Example: a script can call a sibling module function

main.ocelot-script:

```ocelot
helper::greet();
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# How do nested directories affect module names?

Nested directories contribute additional `::` segments to the module path.

## Example: a script can call a nested module function

main.ocelot-script:

```ocelot
math::greet::hello();
```

math/greet.ocelot:

```ocelot
fun hello() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when a referenced module does not exist?

Qualified calls fail in the resolver when their module path does not match any loaded file module.

## Example: calling an unknown module is a resolver error

main.ocelot-script:

```ocelot
helper::greet();
```

### Error

```text
error: unknown module `helper`
  ╭▸ main.ocelot-script:1:1
  │
1 │ helper::greet();
  ╰╴━━━━━━━━━━━━━ unknown module
at main.ocelot-script:1:1
```

# What happens when a module exists but does not export the requested function?

The resolver should report that the module is known but the named function is missing.

## Example: calling a missing module function is a resolver error

main.ocelot-script:

```ocelot
helper::greet();
```

helper.ocelot:

```ocelot
fun wave() {}
```

### Error

```text
error: module `helper` has no function `greet`
  ╭▸ main.ocelot-script:1:1
  │
1 │ helper::greet();
  ╰╴━━━━━━━━━━━━━ unknown function
at main.ocelot-script:1:1
```

# How does a module run directly without top-level statements?

Running a `.ocelot` file directly resolves the module defined by that file and calls its `main()` function.
The `main()` function is not a special declaration form.
It is just the conventional module entrypoint name used for direct module execution.
In this first slice, `main()` follows the ordinary function syntax and therefore takes no parameters.

## Example: a module can define a `main()` entrypoint

main.ocelot:

```ocelot
fun main() {
    helper::greet();
}
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when a directly executed module does not define `main()`?

Direct module execution requires a module-local `main()` function.
If it is missing, startup fails with a dedicated error instead of silently doing nothing.

## Example: a module without `main()` cannot run directly

main.ocelot:

```ocelot
fun helper() {}
```

### Error

```text
module `main` does not define a `main()` entrypoint
```

# What happens when a module file contains a top-level statement?

Module files reject ordinary top-level statements because that syntax is reserved for `.ocelot-script` files.

## Example: a module file cannot contain a top-level statement

main.ocelot:

```ocelot
println("hello");
fun main() {}
```

### Error

```text
error: top-level statements are only allowed in `.ocelot-script` files
  ╭▸ main.ocelot:1:1
  │
1 │ println("hello");
  ╰╴━━━━━━━━━━━━━━━━━ move this statement into `main()` or rename the file to `.ocelot-script`
at main.ocelot:1:1
```
