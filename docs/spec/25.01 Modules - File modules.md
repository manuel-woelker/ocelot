# How are files mapped to modules?

Every `.ocelot` file defines a module. Its name is its path relative to the
execution root, without the extension and with path separators replaced by `::`.
For example, `helper.ocelot` defines `helper`, and `math/greet.ocelot` defines
`math::greet`. Every function defined in a module is exported.

The engine eagerly loads all `.ocelot` files beneath the entry file's directory.
Scripts use the `.ocelot-script` extension; their startup behavior and the
restriction on module top-level statements are specified in
[file execution](./28.01%20Runtime%20behavior%20-%20Scripts.md).

Functions are available through qualified calls or file-local
[imports](./25.02%20Modules%20-%20Imports.md). See [core lookup](./25.03%20Modules%20-%20Core%20module.md) for unqualified name precedence.

# How does a script call a sibling module function?

The entry file can call a function exported from a sibling file by naming the sibling module explicitly.

## Example: a script can call a sibling module function

main.ocelot-script:

```ocelot
helper::greet();
```

helper.ocelot:

```ocelot
fun greet() {
    println("hello");
}
```

### Output

```text
hello
```

# How do nested directories affect module names?

Nested directories contribute additional `::` segments to the module path.

## Example: a script can call a nested module function

main.ocelot-script:

```ocelot
math::greet::hello();
```

math/greet.ocelot:

```ocelot
fun hello() {
    println("hello");
}
```

### Output

```text
hello
```

# What happens when a referenced module does not exist?

Qualified calls fail in the resolver when their module path does not match any loaded file module.

## Example: calling an unknown module is a resolver error

main.ocelot-script:

```ocelot
helper::greet();
```

### Error

```text
error: unknown module `helper`
  ╭▸ main.ocelot-script:1:1
  │
1 │ helper::greet();
  ╰╴━━━━━━━━━━━━━ unknown module
at main.ocelot-script:1:1
```

# What happens when a module exists but does not export the requested function?

The resolver reports that the module is known but the named function is missing.

## Example: calling a missing module function is a resolver error

main.ocelot-script:

```ocelot
helper::greet();
```

helper.ocelot:

```ocelot
fun wave() {}
```

### Error

```text
error: module `helper` has no function `greet`
  ╭▸ main.ocelot-script:1:1
  │
1 │ helper::greet();
  ╰╴━━━━━━━━━━━━━ unknown function
at main.ocelot-script:1:1
```
