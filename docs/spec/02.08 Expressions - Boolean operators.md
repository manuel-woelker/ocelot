# What do `and` and `or` produce?

`and` and `or` are reserved keywords. Both require boolean operands and produce
`bool`. There are no implicit truth-value conversions. A chain of the same
operator is allowed; mixing different operators requires
[parentheses](<02.07 Expressions - Parentheses.md>).

## Example: boolean operators follow their truth tables

main.ocelot-script:

```ocelot
println(false and false);
println(false and true);
println(true and false);
println(true and true);
println(false or false);
println(false or true);
println(true or false);
println(true or true);
```

### Output

```text
false
false
false
true
false
true
true
true
```

# When is the right operand evaluated?

Evaluate left exactly once. `and` skips right when left is false; `or` skips right
when left is true. Otherwise evaluate right once. Homogeneous chains proceed
left to right and stop as soon as their result is determined. Errors and returns
only occur along evaluated paths.

## Example: only operands needed for the result perform effects

main.ocelot-script:

```ocelot
fun record(name: string, value: bool) -> bool {
    println(name);
    value
}

println(record(name: "and-left", value: false) and record(name: "skipped", value: true));
println(record(name: "or-left", value: true) or record(name: "skipped", value: false));
println(record(name: "first", value: true) and record(name: "second", value: false) and record(name: "skipped", value: true));
assert((false and {
    assert(false);
    true
}) == false);
assert(true or {
    assert(false);
    false
});
```

### Output

```text
and-left
false
or-left
true
first
second
false
```

# How do returns interact with short-circuiting?

A returning left operand exits the enclosing function before the right operand.
A returning right exits only when it is evaluated. A right operand that always
returns does not make the entire expression non-fallthrough: the left may skip it.
No constant-truth analysis is performed, even for literal left operands.
Parentheses preserve non-fallthrough behavior.

## Example: returns propagate from evaluated operands and preserve the skipped path

main.ocelot-script:

```ocelot
fun guarded(enabled: bool) -> bool {
    enabled and {
        return true;
    }
}

fun fallback(enabled: bool) -> bool {
    enabled or {
        return false;
    }
}

fun early() -> string {
    ({
        return "early";
    }) or {
        println("unreachable");
        false
    }
}

println(guarded(enabled: false));
println(guarded(enabled: true));
println(fallback(enabled: true));
println(fallback(enabled: false));
println(early());
```

### Output

```text
false
true
true
false
early
```

# Are skipped operands still checked?

Yes. Both operands must resolve and type-check, including nested returns and
calls. Both operands' effects are conservatively tracked. Constant conditions
and short-circuiting do not hide invalid names, types, or prohibited effects.
